# AWS-AccessBridge — Web SPA

Scope: `apps/web/**`. Parent index: `../../AGENTS.md`.

Vite React SPA served at `/user/` (canonical entry, protected by Cloudflare Access; `ZERO_TRUST_AUTHENTICATION_PATH = '/user/'` — top-level navigation here triggers the Zero Trust login) with pages under `/user/app/*` (Worker assets + Pages). Entry `src/main.tsx` → `src/SpaApp.tsx` (auth gate via `useAuth`, language state via `hooks/useSpaLanguage`, routing via `hooks/useRouter`, `SpaNavbar` with controlled `LanguageSelector` + toast banner). `src/lib/api.ts` holds the canonical typed `apiRequest<T>` (thrown-`ApiError` model — the **only** request path; the old `apiFetch`/`apiCall` compat layer is gone, having been bypassed in production by every admin tab) plus the generic `readJson<T>` helper (use it instead of `(await res.json()) as T` — the latter trips `no-unnecessary-type-assertion`) and the `ApiError`/`throwForResponse`/`isUnauthorized` plumbing; `src/lib/authOutcome.ts` (`classifyAuthFailure` — pure; 401 → `expired-session`, everything else → `load-failed`, because `useAuth` must not send a user to the Zero Trust login page on a 500), `src/lib/requestGuard.ts` (`createRequestGuard` — the framework-free request-id ordering rule behind `hooks/useRequestGuard.ts`), `src/lib/routes.ts` (`routeForPathname`/`pathForView`/`isAdminPath` — the pathname↔view mapping as pure functions, so it is testable without a DOM; `hooks/useRouter` owns only the `location` read and the popstate listener) and `src/lib/presentation.ts` (`pageNumbers`, `resourceStateColor`, `httpStatusColor` — pure presentation helpers lifted out of `.tsx` so a DOM is not needed to test a windowing function or a colour mapping; keep new pure logic there rather than as a module-private function inside a component, which reads as covered when it is not). `src/lib/format.ts` (locale-aware dates/numbers; `formatAmount` renders a symbol-less "mixed currency" figure when the currency is `null`) and `src/lib/shellExport.ts` (`formatShellExport` — canonical home of the shell snippet, used for both the rendered and the copied text) back presentation (language selection lives in `hooks/useSpaLanguage` + `src/i18n.ts`). `src/lib/constants.ts` holds UI constants (`ZERO_TRUST_AUTHENTICATION_PATH`, `DEFAULT_TEAM_ID`). Components under `src/components/`: feature tabs (`AccountList` + extracted `AccountRoleRow`/`HideRoleConfirmDialog`, `CostDashboard`, `ResourceInventory`, `AuditLogsTab`, `TeamsTab` (handlers only; its three sections are `teams/TeamListSection`, `TeamMembersSection`, `TeamAccountsSection`), `AdminPage` shell + `admin/` one-file-per-tab: `Credentials/Access/Accounts/RoleConfig/SpendAlerts/DataCollection/MaintenanceTab`, `OnboardingWizard` shell + `onboarding/` per-step components + `WizardProgress`, `SpaNavbar`, `AccessKeyModal`) + `ui/` primitives + `Unauthorized` (Zero Trust login button → `ZERO_TRUST_AUTHENTICATION_PATH`, shown on 401s; takes a `reason` so a *failed profile load* gets a reload button instead of a login prompt, since re-authenticating cannot fix a 500). Shared toast state lives in `src/hooks/useToast.ts` (`message`/`showMessage`/`dismiss`, passed down as `showMessage`; `ShowMessage` is the exported prop type — take it rather than re-spelling `(type: 'success' | 'error', text: string) => void`, which was copy-pasted into every feature tab's props). `useToast` holds its dismissal timer in a ref, so a new toast replaces the old one's timer instead of being dismissed early by it and unmounting does not leave a timer calling `setState` on a gone component; domain hooks `useTeams`/`useResources`/`useRouter`/`useOnboardingWizard`/`useSpaLanguage` own fetching/state per vertical slice. Hooks and components that can issue overlapping requests **must** guard against out-of-order resolution — use `hooks/useRequestGuard.ts` (`begin()` / `isCurrent()` / `invalidate()`), never a hand-rolled counter. A slower earlier request must not render after a newer one; search boxes and pagination both trigger the overlap, and the check belongs before *every* `setState` including the loading flag. `AccountList` and `AuditLogsTab` were the two places that had none, which is why the rule now lives in one tested factory rather than in each caller.

`public/favicon.svg` is the bridge-mark favicon and the **single source of truth** for the icon: the `favicon-inline` Vite plugin rewrites the `<link rel="icon">` placeholder in `index.html` into a `data:` URI at build time, so the Worker never has to serve it. Do not paste a data URI into `index.html` — it is generated, and a missing `public/favicon.svg` or a missing placeholder fails the build rather than shipping a broken icon. `public/_routes.json` scopes Pages routing to `/`, `/user`, `/user/*`, `/api/*`, `/docs*`, `/openapi.*`.

Data fetching lives in `src/services/` (`authService`, `accountService`, `costService`, `resourceService`, `teamsService`, `auditService`, `adminService` — module-scope fetchers returning typed data via `apiRequest<T>`, throwing `ApiError`; `apiRequest` is the only request helper). **All** admin mutations go through `adminService`; the seven `components/admin/*Tab.tsx` files used to call the now-removed `apiFetch` directly, which is what left 9 of its 17 functions with no caller — and hid two contract mismatches from it (`cleanupOrphaned` typed `{deleted}` instead of the route's per-table `deletedCounts` + `failures`, and `enableDataCollection` sent a singular `collectionType` where the route requires `collectionTypes`). Mount effects must follow the `useCurrentUser` shape — a single promise chain with `setState` only inside `.then`/`.catch` (never call a component-scope fetcher or set state synchronously in the effect body); event-handler fire-and-forget calls take an explicit `void` prefix. `apiRequest<T>` raises `ApiError` (not `SyntaxError`) for a non-JSON 2xx body so `isUnauthorized` and the `Unauthorized` screen still work.

## Frontend Internationalization

SPA UI strings live in `src/locales/<tag>/translation.json` (12 locales: `en`, `de`, `fr`, `es`, `it`, `nl`, `pt`, `pl`, `ja`, `zh-CN`, `zh-TW`, `ko`) consumed via `useTranslation()` (`t('ns.key', 'English Default')` — always pass the English default so missing keys still render). Rules for new UI text:

- Add the key + English default to `en/translation.json` first, then mirror it into the other 11 locale files (same key order). Validate with `pnpm run validate:locales` (`scripts/i18n/validate_locales.ts`, rules in `scripts/i18n/locale-checks.ts`, unit-tested in `test/scripts/locale-checks.test.ts`; a `locales` CI job and `pnpm run checks` both run it): JSON-valid, key parity incl. no extra keys, `{{placeholder}}` parity, no empty or non-string values, **in `en` as well as the others** — `en` is the fallback for every missing key and every `t()` call passes an English default, so an empty value there is indistinguishable from a missing one and is what a user actually sees. It also cross-checks the three lists of supported tags: `SUPPORTED_LANGUAGES` (`src/i18n.ts`) and `SUPPORTED_LOCALES` (`shared/utils/LocaleUtil.ts`) must agree with each other and with the `locales/<tag>/` directories. A tag declared with no directory makes `loadLanguage` throw; a directory no tag names can never be loaded. The tag lists are parsed from source text rather than imported, because `src/i18n.ts` calls `import.meta.glob` and only exists after Vite's transform. Key **order** is deliberately not checked.

- Lazy loading: `src/i18n.ts` code-splits per-locale chunks (`loadLanguage`, `import.meta.glob`; `normalizeLanguage` delegates to shared `LocaleUtil`); never statically import a non-English locale (only `en` is static; breaks code-splitting — see Vite `INEFFECTIVE_DYNAMIC_IMPORT` warning).
- Detection precedence: backend `preferredLanguage` (`GET /user/me`) > `localStorage('aws-access-bridge-lng')` > `navigator.language` > `en`. `hooks/useSpaLanguage` owns it (explicit `language`/`languageStatus`/`languagePending`, `languageChanged` listener, `<html lang>` sync, backend-authoritative save `load → PUT → localStorage → setUser`, `unknown` error state disabling the controlled `LanguageSelector`).
- Dates/numbers: `lib/format.ts` helpers take optional `lng` (pass `i18n.resolvedLanguage`); ad-hoc `toLocale*()` must pass an explicit locale, never rely on the ambient default.
- There is no backend locale bundle. `shared/src/i18n/` and its twelve empty `strings: {}` tables were removed: no `src` file called `getBackendStrings`, every table was empty, and all twelve declared `locale: 'en'` — so `getBackendStrings('de').locale` returned `'en'` and a test asserted that wrong answer as correct. `validate:locales` covers the web catalogs only, and a passing check says nothing about server-side text. If backend-side translation is ever added, start from `LocaleUtil`/`SUPPORTED_LOCALES` and add a validator in the same change — do not reintroduce unvalidated tables. API error `Message` strings stay English (stable `Type` codes); translate display-side only.

## Web UI Text Conventions

**English-source** user-visible text in `apps/web/` must use **Title Case**. Applies to: button labels, headings, card titles, section headers, form labels, placeholders, empty-state messages, toasts, confirm dialogs, `aria-label`, `<option>` text. Translations use each language's natural casing (Title Case is English-only).

**Never hardcode ALL CAPS in JSX.** Use CSS (`uppercase` Tailwind / `text-transform: uppercase`) instead.

**Exceptions** (no Title Case): `<code>` content, technical URI placeholders, dynamic API response content.
