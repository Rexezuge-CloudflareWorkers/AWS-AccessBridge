# AWS-AccessBridge — API Worker

Scope: `apps/api/**`. Parent index: [`../../AGENTS.md`](../../AGENTS.md). Workspace and layer rules: [`../../docs/agents/repo/AGENTS.md`](../../docs/agents/repo/AGENTS.md).

- `src/types.d.ts` — references the generated `worker-configuration.d.ts` plus the checked-in
  `packages/backend-runtime/src/env.d.ts`, which is the binding source of truth.
- `src/generated/spa-shell.ts` — generated by the web build. Do not edit.
- `src/schema/` — thin re-export layer over `@aws-access-bridge/shared/schema`.

## The worker

`src/workers/AccessBridgeWorker.ts` builds a Hono app and wraps it with `fromHono`, serving OpenAPI
at `/docs` and `/openapi.json` (both public). Middleware order is load-bearing:

```
app.use('*',  MiddlewareHandlers.hmacValidation())
app.use('/user/*', noStore())        // registered BEFORE the auth handlers
app.use('/api/*',  noStore())
app.use('/user/*', activityAudit())
app.use('/api/*',  activityAudit())
app.use('/user/*', userAuthentication())
app.use('/api/*',  apiAuthentication())
```

`noStore` awaits `next()` and sets the header afterwards, so it must **wrap** rather than sit behind
the auth handlers — one of those returns its JSON directly without calling `next()`, and the header
would never be set. Every response on both surfaces carries AWS credentials, a session token, a
15-minute pre-authenticated console URL, or account and audit data; without `Cache-Control: no-store,
max-age=0` and `Pragma: no-cache` an intermediary or the browser back/forward cache could replay them.

Routes are registered in seven groups — `registerAws/UserAccount/AdminAccount/Cost/Resource/Team/
MaintenanceRoutes` — plus `registerApiRoutes`. `onScheduled` forwards to the `CRON_TASKS` DO over its
own fetch inside `ctx.waitUntil`, logging a non-OK response and swallowing nothing else.

### The SPA catch-all is unconditional, and only serves `/user/`

Any unmatched path beginning `/user/` serves the embedded `SPA_HTML`; everything else 404s, so
`/api/*` is never intercepted. Pages are namespaced under `/user/app/*` precisely so they cannot
collide with `/user/*` JSON routes like `GET /user/resources` or `GET /user/admin/teams`.
`assets` is declared with `run_worker_first` unset, so `/assets/*` is served by the asset router
before this handler runs.

`/` redirects to `/user/` (the canonical entry — top-level navigation there triggers the Zero Trust
login), `/user` normalises to `/user/`, and the legacy `/costs`, `/resources`, `/admin/*` redirect
to their `/user/app/*` equivalents.

## Endpoints

One thin class per route under `src/endpoints/`, extending one of two bases:

- `IActivityAPIRoute.ts` — `handle` → `handleRequest` Template Method, plus `toResponse`,
  `toErrorResponse` and `getQueryParam`. Session, demo-mode and base-URL concerns are extracted to
  `route-helpers.ts`.
- `IAdminActivityAPIRoute.ts` — adds the demo-mode block and the superadmin guard.

**Every `handleRequest` / `handleAdminRequest` takes the context as its third argument**, even when it
needs nothing else for that. The context _is_ the request's identity, and without it a handler cannot
reach the per-request scope: the `WeakMap` is keyed on the context precisely because
`route-helpers.withUnconstrainedD1Session` spreads `c.env` into a _new_ object, so an env-keyed
lookup missed on every request.

Routes resolve domain services with `getRequestScope(cxt).get(Tokens.X)` — never
`new XService(env)` — and never import DAOs (ESLint `no-restricted-imports`, type-only imports
excepted).

`toErrorResponse` returns typed messages for **4xx only**. A 5xx, including `DatabaseError` whose
message embeds raw D1/SQLite text, is logged and answered with the generic
`DefaultInternalServerError`.

## Error responses declare one envelope

`@aws-access-bridge/shared/schema/exceptionResponses` holds status-keyed builders
(`badRequestResponse`, `unauthorizedResponse`, `forbiddenResponse`, `notFoundResponse`,
`conflictResponse`, `internalServerErrorResponse`) for the `{Exception: {Type, Message}}` shape. Use
them rather than inlining a schema; 147 openapi error blocks were collapsed into them.

Two properties are load-bearing and asserted:

- **401 and 403 stay distinct.** The SPA's `isUnauthorized` keys on 401 alone, so a 403 rendered as
  401 sends an administrator to the Zero Trust login page for something re-authenticating cannot fix.
- **The documented 500 message is generic.** `DatabaseError` embeds raw D1/SQLite text and
  `toErrorResponse` already answers a 5xx with `DefaultInternalServerError`, so an example quoting a
  real internal message would advertise a shape the server never emits.

The builders return a `type` alias rather than an interface because Chanfana's `SchemaObject` carries
an `x-<string>` index signature, which only a type alias satisfies.

## Auth

### `/user/*` — Cloudflare Access

`AccessAuthService.getAuthenticatedUserEmail` resolves in order:

1. `DEMO_MODE` → `demo@example.com`.
2. `DEV_AUTH_EMAIL` (local-only; see below).
3. JWT verification via `jose` against `{TEAM_DOMAIN}/cdn-cgi/access/certs` with audience
   `POLICY_AUD`, reading the `cf-access-jwt-assertion` header and taking `payload.email`.
4. The platform-verified `ctx.access.getIdentity()` fallback, used only when `TEAM_DOMAIN` **and**
   `POLICY_AUD` are both unset — Worker-level Access, for same-account one-click deploys.

Explicit vars always win over the fallback when set. **Never trust the spoofable
`Cf-Access-Authenticated-User-Email` request header**; that is locked by tests.

`DEV_AUTH_EMAIL` has no default and is local-only. It is read _before_ JWT verification from an
ordinary var, so without a guard a `.dev.vars` promoted by mistake would authenticate every caller
as that address, super-admin included. So it throws `InternalServerError` when
`ConfigurationManager.environment.isProduction(env)` — which is only the literal `production`, not
`prod` and not unset. The integration suite sets `DEV_AUTH_EMAIL` in vars and therefore keeps
working.

### `/api/*` — PAT or internal HMAC

Either a Bearer PAT (`TokenService.authenticateWithPAT`) or an HMAC-signed internal self-call
(`X-Internal-*` + `X-Internal-User-Email`, after `hmacValidation()`).

**A valid internal signature is rejected on a second presentation.** `HMACHandler` verifies that a
request was _authored_ by the secret holder, not that it is presented once. The
±`INTERNAL_REQUEST_VALID_TIME_WINDOW_MILLISECONDS` check bounds how long a capture stays replayable,
but every request inside that window still replays, and `authenticateApiIdentity` trusts the
`X-Internal-User-Email` header on it. `ReplayGuard` records an accepted signature in the existing
`AccessBridgeKV` and refuses a second presentation, keyed on the signature itself so the signing side
needs no nonce and every pre-existing signature keeps working. It is claimed **only after**
verification — a forgery must not be able to poison the seen-set — and it **fails open**: a missing
binding or a KV error returns `true`, because the timestamp window still bounds replay and a KV
outage should not cost the whole `/api/*` internal surface. The failure is logged, never silent.

`authenticateWithPAT` takes an optional `defer` callback. The `last_used_at` stamp is a D1 write that
`updateLastUsedByToken` throws on, so the middleware hands it `ctx.waitUntil` rather than awaiting it
on the auth path — a write-side blip must not turn a valid PAT into a 500.

### Identity and auditing

`AuthenticatedUserEmailAddress` is the address the request authenticated as;
`AuthenticatedUserId` is the stable account key it resolves to, published best-effort by
`MiddlewareHandlers.publishAccountId`. A failure there logs and continues, because the address alone
is still a complete identity. Both are read through `IActivityAPIRoute.getAuthenticatedUserEmailAddress`
/ `getAuthenticatedUserId`; routes and the OpenAPI surface stay address-based by design, since the
services resolve the account internally.

Every `/user/*` and `/api/*` call is audited by `activityAudit()`, which builds the event through
`AuditService` and writes it in `waitUntil` with its own `.catch` — a rejected audit write must not
become an unhandled rejection. The event carries the account id alongside the address, best-effort and
absent on a database without migration 0032, so an entry stays findable after an address change.

### Rules

- Never import `aws4fetch` or `@aws-access-bridge/provider-clients` in `apps/api`; both are
  ESLint-restricted. Route AWS SDK usage through `@aws-access-bridge/backend-services`.
