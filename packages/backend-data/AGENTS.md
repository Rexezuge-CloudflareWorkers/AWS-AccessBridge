# AWS-AccessBridge — Backend Data (D1/DAO Layer)

Scope: `packages/backend-data/**`. Parent index: `../../AGENTS.md`.

All D1 access via DAOs extending `dao/BaseDAO.ts` (`BaseDAO` — `ctor(database: D1Queryable)`, `withRetry()`, static `findById`/`deleteOlderThan` with SQL-identifier allow-list, instance `findRowById`/`deleteRowsOlderThan` push-downs; `EncryptedDAO` — adds `masterKey` for encrypted rows, e.g. `CredentialsDAO`): `CredentialsDAO`, `AssumableRolesDAO` (+ `AssumableRolesQueries` shared SQL fragments + `AssumableRolesMapper.mapRowsToAssumableMap` pure mapper), `AwsAccountsDAO`, `RoleConfigsDAO`, `UserMetadataDAO`, `UserEmailDAO`, `UserFavoriteAccountsDAO`, `UserAccessTokenDAO`, `AuditLogDAO`, `CostDataDAO`, `DataCollectionConfigDAO`, `SpendAlertDAO`, `ResourceInventoryDAO`, `CredentialCacheConfigDAO`, `CredentialsCacheDAO` (KV), `BackgroundTaskRunDAO`, `TeamsDAO`, `TeamMembersDAO`, `TeamAccountsDAO`; `IKeyValueDAO` KV contract (`get`/`put`/`delete` all namespace the key — `delete` must too); `crypto/` (`aes-gcm`, `hmac` for AES-GCM credential encryption + internal HMAC signing — `encryptData` deliberately takes no caller-supplied IV, see below); `constants/` (`kv/` namespaces/TTL/value-type, `d1/` session constraints); `utils/` (`D1Utils.executeD1WithRetry` + `assertD1Success`, `D1ErrorClassifier.isD1ErrorRetryable` + `isMissingSchemaError` (missing-table/column only — never swallow a constraint violation or timeout), `D1SessionUtil` (`D1Queryable`, `createD1SessionEnv`)).

**User identity (`migrations/0032_user_identity.sql`)**: `user_metadata.user_email` is the frozen **anchor** — never updated, still the primary key, and still the target of live foreign keys from `assumable_roles`, `user_favorite_accounts` and `user_access_tokens` (the last `ON DELETE CASCADE`). D1 honours neither `PRAGMA foreign_keys = off` nor `PRAGMA legacy_alter_table = on`, and `defer_foreign_keys` does not suppress `ON DELETE CASCADE`, so those references cannot be repointed without losing rows; the migration is purely additive for that reason. `user_metadata.id` (`usr_<hex>`) is the stable account key; `current_email` is the mutable sign-in address; `user_emails` is the address registry (`is_verified = 1` may authenticate). So a `*_email`/`created_by` column is written with the **anchor** (it is the FK target and, for `assumable_roles`/`user_favorite_accounts`/`team_members`, half of a primary key), while identity-keyed reads and writes go through `user_id`. `0032` assigns `current_email` only where the lowercased address is unambiguous, so a live database holding both `Alice@x.com` and `alice@x.com` is neither merged (a privilege escalation) nor failed (a unique-index violation); those rows keep `current_email IS NULL` and resolve via the anchor. User-keyed DAO methods therefore take an owner object — `AssumableRoleOwner` (`{userId, anchorEmail}`) or `TeamMemberOwner` — not a bare address, and the shared predicate is `ownerClause(alias)` = `(alias.user_id = ? OR (alias.user_id IS NULL AND alias.user_email = ?))`; the `IS NULL` guard is load-bearing, since without it an address an account has moved away from would also match a different account's row. `UserMetadataDAO.ensureUserEmailExists` stamps `id`/`current_email` on insert — a row created after 0032 is never backfilled again, so provisioning without them leaves a permanently unresolvable account.

**Credential encryption**: every encrypted field gets its own random 96-bit AES-GCM IV, stored in its own column (`salt`, `salt_secret_access_key`, `salt_session_token`). Never reuse an IV across fields under one key — it leaks the XOR of the plaintexts and enables tag forgery. `encryptData` therefore accepts no IV argument. Rows written before `migrations/0031_distinct_credential_ivs.sql` carry only `salt`; reads fall back to it (`CredentialsDAO.resolveIv`, and the same fallback in `CredentialsCacheDAO`), so old rows keep working and are upgraded on their next write.

The 7 `deleteOrphaned()` implementations write their own inline SQL; `BaseDAO.deleteOrphanedRows` exists but is not used by any of them.

Conventions: DAOs extend `BaseDAO`/`EncryptedDAO` (never redeclare `database`); failed writes throw `DatabaseError` on `!result.success` (`retryable` flag drives `executeD1WithRetry` backoff); batch deletes expose `deleteOlderThanBatch(cutoff, batchSize): Promise<number>` (D1 `DELETE … LIMIT ?`, `meta.changes ?? 0`) for `AbstractPruningTask`; models use dual camelCase/snake_case `Type`/`TypeInternal` pairs from `@aws-access-bridge/shared/model`. Routes must not import DAOs (ESLint-enforced in `apps/api/src/endpoints/**`, type-only imports excepted) — compose `backend-services` domain services instead.
