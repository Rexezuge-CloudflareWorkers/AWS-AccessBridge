# AWS-AccessBridge — Backend Services (Business Logic)

Scope: `packages/backend-services/**`. Parent index: `../../AGENTS.md`. Feature details: `../../docs/agents/features/*/AGENTS.md`.

Instance services by domain (constructor-injected `ServiceEnv`; resolve per-request via `getRequestScope(cxt).get(Tokens.X)` from `composition/` — the DI composition root, and the only supported way to construct a service): `identity/` (`resolveOwner(identity, userEmail)` is the **single** translation from a sign-in address to the `{userId, anchorEmail}` owner that every user-keyed DAO statement is keyed on; the `{userId: idOf(account), anchorEmail: account?.anchorEmail ?? userEmail}` pair was written out fifteen times across seven services — with `AccessService` and `AssumeRoleService` inlining it at their call sites rather than calling a helper at all — so use it instead of re-deriving either half), `UserIdentityService` — address → account resolution: `user_emails` registry first (only `is_verified = 1` may authenticate, so a revoked address never resolves), then `user_metadata.current_email`, then the frozen anchor as the pre-0032 floor; memoized per request scope; `resolveAccount`/`resolveUserId`/`resolveAccountById`, delegating `listAddresses`/`setPrimaryEmail`/`linkVerifiedEmail` to a composed `AddressRegistryService` (address *management* is a separate class because its safety argument — claim-then-revoke ordering, case-insensitive claim checks — is a different one from resolution's; the resolver re-exposes the methods so callers still hold one object), plus `idOf(account)` — the one place an empty id becomes `null` for a `user_id` write, since binding `''` fails the 0032 foreign keys), `credential/` (`CredentialChainService` — chain resolution incl. cache-short-circuit, and the per-feature key chains for both encrypted surfaces; `CredentialStoreService` — store/relationship CRUD + STS validate. The old `CredentialService` facade over both is gone: it was self-documented as kept only for compatibility, every method forwarded to one of these two, and it was still the token every caller resolved. `CredentialChainWalker` Template Method with `LeafCredentialsWalker`/`ChainTestWalker`), `aws/assume-role/` (`AssumeRoleService` — access check → chain → cached-hop reuse → chain walk; an intermediate hop is cached only when it has **both** an expiration and a session token, since the read path short-circuits on a hit and a tokenless entry would be handed straight back to STS), `aws/console/` (`ConsoleService` — signin tokens, login/issuer/destination URL builders), `aws/sts|iam|ce/` (thin domain delegates over raw `provider-clients` `StsClient`/`IamClient`/`CostExplorerClient`), `aws/collectors/` (`IAwsResourceCollector` Strategy + `BaseAwsCollector` Template base — owns the signed fetch, the non-OK decision, and body parsing via `fetchText`/`fetchJson`/`fetchJsonWithInit`, which all 5 collectors use; a non-OK response or a malformed body **throws** `AwsCollectionError` (carrying `status` + `resourceType`, with `retryable` set for 429/5xx) rather than resolving to `[]`, because `ResourceInventoryCollectionTask` prunes previously collected rows for every type that "succeeded" and an empty list from a 403 would delete a real account inventory — the task catches per collector and skips pruning for any type that threw, while an empty-but-successful call still prunes — + `CollectorRegistry` statics + `InjectableCollectorRegistry.withDefaults/withOverrides` seam: `Ec2/S3/Lambda/Rds/DynamoDbCollector`), `auth/` (`AccessAuthService` — Access JWT/demo/dev; `TokenService` — PAT auth + token CRUD; `authenticateWithPAT` resolves the owner's CURRENT address from the token's `user_id` rather than the stored anchor, so a token minted before an address change does not authenticate as the old address forever — and quota/ownership are id-keyed with an address fallback), `account/` (`AccountService` — nicknames, role configs, role discovery), `access/` (`AccessService` — grant/revoke), `user/` (`UserService` — profile, favorites, hidden roles, assumables; preferred-language writes/reads normalized via shared `LocaleUtil`). Services taking the caller still take their sign-in ADDRESS and resolve the account internally (`this.identity.resolveAccount`) rather than accepting an id — the authenticated principal at the edge is always an address, so the id is a read-path implementation detail and the route/OpenAPI/web surface stays unchanged. Every write provisions and writes against the resolved **anchor**, never the presented address; `AssumeRoleService`'s `userId` local is the STS `RoleSessionName` (from `federation_username`), NOT the account id, `user/` (`UserService` — profile, favorites, hidden roles, assumables; preferred-language writes/reads normalized via shared `LocaleUtil`), `cost/` (`CostService` — summary/account/trends, alerts, collection config), `resource/` (`ResourceService` — search/summary), `team/` (`TeamService`), `maintenance/` (`MaintenanceService` — orphan cleanup, task runs; `cleanupOrphanedData` settles its seven table deletes **independently** and reports per-table `failures`, because running them in sequence let one busy table abort the other six and answer 500 with no indication of how far it got), `audit/` (`AuditService` fan-out via `AuditObserverRegistry` + `AuditPayloadBuilder` request→event mapping + `AuditEventBuilder` + `AuditLogObserver`; `AUDIT_ACTIONS` map; `ListAuditLogsRoute` resolves the searched address to an account id and passes **both** to `AuditLogDAO.query` — the address arm of the owner predicate is the `user_id IS NULL` fallback, which an attributed row never takes, so filtering by a *current* address alone returned nothing after a user's address changed), `composition/` (`ServiceEnv` — the single source of truth for what a service may read; `Tokens` (incl. `UserIdentityService`, bound once per request scope so the address→account memo is a per-request cache); `createRequestScope`; `getRequestScope` — takes **either** a Hono context or a bare env and keys a `WeakMap` on whichever it is given. Request handlers must pass the context: keying on `env` looks right (Workers hand one object to every handler in a request) but `route-helpers.withUnconstrainedD1Session` spreads `c.env` into a *new* object, so an env-keyed lookup missed on every request and built two or three containers where there should be one — two or three secret fetches, and the identity memo re-running. Cron/DO tasks pass `env` (there is no context), and build a **fresh** scope per run via `createRequestScope` rather than the cached one, because a Durable Object's `env` is stable for the object's lifetime and a cached scope would pin the memoized encryption keys after a rotation); `encryptionKeys.ts` — the per-feature key chains (`Tokens.CredentialKey`, `Tokens.CredentialCacheKey`), **injected** into `CredentialChainService`/`CredentialStoreService` by the composition root rather than looked up by them: a service holds only `env`, which is not the request's identity, so a lookup inside one would build a second scope; `http/` (`IHttpClient` → `FetchHttpClient`/`StubHttpClient` with `queueJson/queueError/setHandler/calls` + `fetchJson` + `HttpFetchError`/`isRetryableHttpStatus`; `AwsClient*` types re-exported from `provider-clients`), `http/` (`IHttpClient` → `FetchHttpClient`/`StubHttpClient` + `RetryingAwsClient`, which retries 429/5xx with exponential backoff and full jitter and honours `Retry-After`).

Pure static utilities stay static (Otter precedent): `aws/ArnUtil`, `aws/BaseUrlUtil`, `aws/InternalRequestHelper` (instance, holds fetcher+secret), `error/` (`ErrorTranslationUtil`, `ErrorDeserializationUtil`).

Related packages: `shared/` (constants incl. canonical `StsMessages`/`HmacMessages`, models, schemas, utils `TimestampUtil` (current-time reads take an optional `Clock`, defaulting to `SystemClock`; `HMACHandler` takes one so the replay-window edge is testable), `Clock`/`SystemClock`/`FixedClock`, `UUIDUtil`, `RequestOriginUtil`, `EmailUtil`, `LocaleUtil`, `RegexUtil.matchAll` (no `i18n/` — the empty backend locale bundles were deleted)), `backend-errors/` (`BadRequestError`, `UnauthorizedError`, `ForbiddenError`, `MethodNotAllowedError`, `InternalServerError`, `DatabaseError` (+`retryable`), `IServiceError`), `backend-runtime/` (env `ConfigurationDefaults`, `ConfigurationManager` namespaced getters + `EnvParser` — all tunables are `DEFAULT_*` _string_ constants parsed on read, and an unparseable value falls back to the default rather than throwing; `di/` `Container` (`bind`/`bindValue`/`get` only — the former `resolve`/`has`/`createChild` were dead and removed; per-request scoping comes from a fresh container, not a non-memoizing resolve); abstract worker bases `AbstractEntrypointWorker`, `AbstractDurableObjectWorker`; DO naming constants + `Pagination`; checked-in `env.d.ts` binding source of truth), `provider-clients/` (raw AWS: `AwsSignedFetcher` + `StsClient`/`CostExplorerClient`/`IamClient`).
