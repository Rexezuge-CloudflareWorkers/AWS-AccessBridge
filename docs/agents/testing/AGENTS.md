# AWS-AccessBridge — Testing

Scope: unit + integration + emulator tests. Parent index: [`../../../AGENTS.md`](../../../AGENTS.md). Commands and the rest of the gate list: [`../repo/AGENTS.md`](../repo/AGENTS.md).

Current thresholds (`vitest.config.mts`): **statements 94 / branches 83 / functions 94 / lines 94**, a little under the measured 94.03 / 83.11 / 94.17 / 94.45 so ordinary churn does not fail the build but a real regression does.

**There is a second, per-file gate: `pnpm run check:coverage-floor`** (`scripts/check-coverage-floor.mjs`), wired into `pnpm run checks` after `test:coverage`. An aggregate threshold can be met while a single security-critical file rots — `MiddlewareHandlers` sat at 61.5% branch coverage, the whole auth chain, while the project total looked healthy enough to keep raising the bar past. The gate pins 34 files carrying the **auth boundary** (`MiddlewareHandlers`, `RequestGuards`, `HMACHandler`, `AccessAuthService`, `TokenService`, `ReplayGuard`, `UserIdentityService`, `crypto/hmac`), **request validation** (`schema/input.ts`, `schema/common.ts`, `RequestOriginUtil`, the route bases), **credential encryption and chain resolution** (`aes-gcm`, `CredentialChainService`, `CredentialChainWalker`, `AssumeRoleService`, `CredentialStoreService`), **the outbound deadline** (`FetchTimeout` — every AWS call is bounded by it), **data integrity** (`UserAccessTokenDAO`, `CredentialsDAO`, `BackgroundTaskRunDAO`, `AssumableRolesDAO`, `AuditLogDAO`), the **background pipeline** (`CronTasksWorker`, `CronTask`, the collection tasks), **authorization decisions** (`CostService`, `TeamService`), **routing** (`AccessBridgeWorker`), and **logging** (`Logger` — a leak there is silent). It reads `coverage/lcov.info`, so `test:coverage` must run first.

A split that moves code out of a pinned file has to move the floor with it. `RequestGuards` is the case in point: extracting the pre-authentication guards left `MiddlewareHandlers` comfortably above its floor while the new file — the one whose branches decide whether a request is refused — had none. Floors are measured figures minus a few points, keyed by path _suffix_ so a file move does not silently drop one; a floor naming an absent file **warns rather than fails**, so stale config is never the thing that blocks a deploy.

Coverage `include`: `apps/api/src/**`, `apps/background/src/**`, `apps/web/src/services/**` + `apps/web/src/lib/**`, `packages/**/src/**`. Exclusions: the kit factory's barrels/type-only set (`**/*.test.ts`, `**/*.d.ts`, `**/index.ts`, `**/types.d.ts`, `**/types.ts`, `**/model/**`, `**/generated/**`, `**/env.d.ts`, `scripts/**`) plus `apps/api/src/schema/**` (pure `export *` shim over `shared`), `composition/ServiceEnv.ts` + `composition/tokens.ts` (types only), and `apps/background/src/CollectionWorkflow.ts` — a Workflow class is a platform entrypoint like a DO class, constructible only inside the Workers runtime; what is worth asserting about it is asserted against `CronTasksWorker` instead.

Two Vitest projects: `backend` (`test/**/*.test.ts`) and `web` (`test/**/*.test.tsx` under jsdom with `test/setup/dom.ts`, `@testing-library/jest-dom` + Testing Library `cleanup`). A `.tsx` file is the marker for the second, so a component test written as `.ts` would silently run in `backend` and fail on `document`.

`test/web-dom/` covers `useToast`, `useAuth`, `useTeams` and `useAccountMutations` — the first two for behaviour only a renderer can show (a ref-held dismissal timer, the 401-vs-500 auth gate), the last two because the request guard's _wiring_ and an optimistic rollback are only observable under React. `test/web/WebPureLogic.test.ts` is the counterpart for the pure modules the refactor moved out of components and hooks (`pagination`, `numbers`, `storage`, `roleSelection`, `costTrends`, `teamRoles`, `asyncAction`, `onboardingWizard`) — the only reason they count toward coverage at all, since a rule inside a `.tsx` reads as covered when it is not. Hooks and components stay out of the coverage `include`: they are JSX-heavy and mostly markup. Their pure logic is expected in `lib/`, where it does count.

`test/floci/**` is excluded from both projects, and `test:floci` is deliberately **not** in `pnpm run checks`, so the local gate never needs a container.

**`vi.spyOn` does not work on an ESM module namespace** — the namespace is frozen, so the spy silently does nothing and the real implementation is reached instead. Mock collaborators with `vi.mock` plus a mutable holder (`test/middleware/AuthChain.test.ts`, `test/tasks/CollectionTasks.test.ts`), not a namespace spy.

Integration tests in `test/integration/` use `@cloudflare/vitest-pool-workers` (no V8 coverage — no thresholds there, omitted intentionally).

**Integration** (`test/integration/api/`): `UserMe` (profile + OpenAPI), `AdminGuard` (non-super-admin 403 matrix over 9 admin routes + unauthenticated `/api/*` 401s), `UserData` (empty assumables/costs/resources + full PAT mint→list→use→revoke lifecycle incl. 400-proves-auth and revoked-401), `AssumablesPagination` (the hidden-role filter scoped to its paging subquery), `TokenHashing` (the 0034 migration: no plaintext anywhere in a token row, the digest is 64 hex, the minted token authenticates and a near-miss does not), `CredentialEncryption` (distinct-IV write, legacy-row read, re-encrypt-on-rewrite, tamper rejection, two-hop chain walk, `/__scheduled` absent — all against real D1), `CredentialPrewarm` (the pre-warm task against real D1 and KV with stubbed STS: a length-1 principal is skipped cleanly, only intermediate hops are cached, the attempt clock advances), `RetentionPruning` (the pruning tasks against real D1, including the `rowid IN (SELECT …)` form that replaces `DELETE … LIMIT`), `FetchTimeout` (the outbound deadline **under workerd rather than Node**: a stalled mid-body response and a never-settling `send` both become a retryable `BadGatewayError`, a rebuilt response keeps its body/headers/status, a 204/304 is not read for a body it may not carry, and a caller's own abort surfaces as `AbortError` rather than a 502), and `UserIdentityUpgrade` (the 0032 identity migration on a _populated_ database: zero row loss, empty `PRAGMA foreign_key_check`, pre-existing FKs and the token `ON DELETE CASCADE` intact, correct `user_id` backfills, a case-variant pair left unresolved rather than merged, an address change leaving id-keyed access intact). The harness injects migrations per-file, and `applyMigrations(db, {from, to})` accepts a range — which is what makes "apply through 0031 → seed → apply 0032" expressible, and "apply 0032 alone" too.

**Floci smoke** (`test/floci/`, `pnpm run test:floci`, the `floci-smoke` CI job) is the only tier that crosses a real network boundary: `sts`/`iam`/`cost-explorer`/`collectors` put the parsers in front of [Floci](https://floci.io), a LocalStack-compatible AWS emulator, on `127.0.0.1:4566`. Every other suite hands our AWS clients a hand-written stub body, which by construction cannot tell us that AWS stopped matching our regexes. Four files: `sts` (incl. a **two-hop cross-account chain** using 12-digit key ids, so hop two only resolves if hop one's session token was parsed and forwarded), `iam` (role discovery incl. `Description` defaulting to `''`), `cost-explorer` (JSON 1.1 + `X-Amz-Target` routing, and a positive amount — the parser drops groups at or below zero, so an empty breakdown would be a pass-by-absence), `collectors` (four of five; S3/RDS seeded non-empty, EC2/Lambda at parse level).

Two findings are worth keeping from this tier. **Query-protocol parameters must ride in the form-encoded body, not the query string** — `awsQueryRequest` in `provider-clients/aws/AwsSignedFetcher.ts` now builds every `StsClient`, `IamClient`, `Ec2Collector` and `RdsCollector` request. AWS accepts either placement, which is why the query-string form shipped without complaint, but the body is the only placement LocalStack-compatible emulators read. And **`DynamoDbCollector` has no emulator coverage at all**: Floci answers `404 UnknownOperationException` for `X-Amz-Target: DynamoDB_20120810.ListTables` _and_ `CreateTable`; its parsing is covered by the stubbed suite, and this is worth revisiting when Floci lands those targets.

**Assert our parser, not Floci's behaviour.** Every claim in these files is one the production code owes, never one about the emulator — three early attempts at the opposite were wrong. Where a value is genuinely ours it is asserted exactly: the total is `MoneyUtil.round(sum)` while breakdown amounts stay unrounded, restated rather than imported so a `MoneyUtil` change surfaces as a contract change.

Four constraints. (1) `test/floci/**` is excluded from the root Vitest projects and `test:floci` is **not** in `pnpm run checks`. (2) **RDS runs in the emulator's metadata-only mode** (`FLOCI_SERVICES_RDS_MOCK=true`, set on the CI service container and in `START_HINT`): a seeded instance is a record write with no backing container and no auth proxy, and 2.2.0's `RetryingDockerHttpClient` makes a missing `/var/run/docker.sock` look like tens of seconds of retry backoff — so the mode is requested explicitly and a per-round-trip deadline (`REQUEST_TIMEOUT_MS`) covers headers **and** the body as one budget. (3) EC2 and Lambda are asserted at parse level, not seeded. (4) Seeds tolerate `EntityAlreadyExists` and friends, so the suite is re-runnable against a long-lived local emulator. The image is **pinned** (`floci/floci:2.2.0`), so a red `floci-smoke` run is our regression until proven otherwise.

The readiness probe is `sts:GetCallerIdentity` through `StsService` in `global-setup.ts`, **not** a ping, followed by warming every collector path the suite touches: a ping only proves _something_ answers, and a stale LocalStack or a leftover process on 4566 answers 200 and then fails every test deep inside a parser. The probe runs once per run and its failure text names all three indistinguishable-from-outside cases: nothing listening, something listening that is not an emulator, and an emulator that answered `2xx` with an unparseable body.

**Never override the CI service container's health check.** The image is the **native** build on `ubi9-micro` — no shell, no `curl`, no `wget` — and it declares its own exec-form check. A `--health-cmd` naming a missing binary makes Docker mark the container unhealthy on the first probe, and GitHub reports only "Failed to initialize container", which reads like a broken image rather than a broken health command. Docker runs a `--health-cmd` string through `/bin/sh -c` inside the container, and ubi9-micro ships no `/bin/sh`, so even a correct script path would fail.

**Mock patterns**:

- DAO tests: `createMockDb()` returning `prepare().bind().run/first/all` chain with shared `vi.fn()` refs.
- Services with DAOs: `vi.mock('@aws-access-bridge/backend-data/dao')`.
- Account resolution (migration 0032): a suite that automocks `UserMetadataDAO` must also automock `UserEmailDAO`, or `UserIdentityService` hits a fake `database` with no `prepare`.
- DAOs that resolve accounts take an injected `UserIdentityService` via a constructor default (`new TokenService(env, identity)`), so a test can pin the account and assert an id-keyed read rather than an address-keyed one.
- AWS clients: `vi.mock('@aws-access-bridge/backend-services/aws/sts')` then `vi.mocked(StsService.prototype.assumeRole)`; same for `CostExplorerService`, `IamService`, `ConsoleService` (partial-mock the module and override only `getSigninToken` to keep URL builders real). Raw parsers tested directly via `provider-clients` clients with stub signed-fetch.
- Collector registry: `vi.mock('@aws-access-bridge/backend-services/aws/collectors')` with a `CollectorRegistry.getAll` returning hoisted stub collectors; `createCollectorRegistry(overrides)` and `InjectableCollectorRegistry.withOverrides` cover the override paths.
- `TokenService`/`AccessAuthService`: direct lifecycle tests with mocked `UserAccessTokenDAO`; `verifyAccessJwt` is pure-static for JWT cases, `getAuthenticatedUserEmail` covers demo/dev bypass.
- Audit: pass stub `IAuditObserver`s to `AuditService`/`AuditObserverRegistry` to isolate fan-out (`Promise.allSettled` isolation asserted).
- Crypto: `vi.mock('@aws-access-bridge/backend-data/crypto')`.
- Cron tasks in worker tests: `vi.mock('@aws-access-bridge/background/scheduled')` with `tasksForPhase` phase stubs.
- Web services: `vi.stubGlobal('fetch', ...)` with fresh `Response` per call (bodies are single-use).
- Use `vi.hoisted()` for mocks referenced across `vi.mock` factories; `beforeEach` + `vi.clearAllMocks()` resets call counts.
- Composition root: `vi.mock('@aws-access-bridge/backend-services/composition')` with `getRequestScope` returning `{ get: () => stub }`.
- **Never re-declare a look-alike of the class under test.** An early `IKeyValueDAO` test defined its own `get`/`put`/`delete` copies, so it asserted the copy's behaviour and a real namespacing bug in `delete` shipped.
- **Assert on the implementation's real contract, not an assumed one.** The SQL allow-list validates the identifier _character set_, not whether a column exists; `EnvParser` coerces a bad value to the default rather than throwing.
- **Await every async assertion.** A missing `await` makes `expect(...).rejects` a no-op.
