**Floci smoke** (`test/floci/`, `pnpm run test:floci`, the `floci-smoke` CI job): the only tier that crosses a real network boundary. Every other suite hands our AWS clients a hand-written stub body, which by construction cannot tell us that AWS stopped matching the regexes in `provider-clients` — so `sts`/`iam`/`cost-explorer`/`collectors` put those parsers in front of [Floci](https://floci.io), a LocalStack-compatible AWS emulator, on `127.0.0.1:4566`. Four files: `sts` (`GetCallerIdentity`, single-hop `AssumeRole`, and a **two-hop cross-account chain** using 12-digit key ids so hop two only resolves if hop one's session token was parsed and forwarded), `iam` (role discovery incl. the `Description`-defaults-to-`''` path), `cost-explorer` (JSON 1.1 + `X-Amz-Target` routing, and a positive amount — the parser drops groups at or below zero, so an empty breakdown would be a pass-by-absence), `collectors` (four of five; S3/RDS seeded non-empty, EC2/Lambda at parse level).

**What this tier found, and why it is worth its cost.** Two of its four files did not exist in this shape before. (1) **Query-protocol parameters must ride in the form-encoded body, not the query string** — `awsQueryRequest` in `provider-clients/aws/AwsSignedFetcher.ts` now builds every `StsClient`, `IamClient`, `Ec2Collector` and `RdsCollector` request. AWS accepts either placement, which is exactly why the query-string form shipped without complaint, but the body is the only placement LocalStack-compatible emulators read. (2) **`DynamoDbCollector` has no emulator coverage at all**: Floci answers `404 UnknownOperationException` for `X-Amz-Target: DynamoDB_20120810.ListTables` _and_ `CreateTable`, so no request shape we can send reaches it. Its parsing is covered by the stubbed suite; revisit when Floci lands those targets. (3) Floci's docs also overstate STS in one place — they promise `AccessDenied` for a role ARN that does not exist, and 2.1.0 instead mints credentials and returns `200`, so no assertion is made about that case.

**The endpoint override is test-side only.** `flociClientFactory` (`test/floci/helpers/floci.ts`) wraps `defaultAwsClientFactory` and swaps the request origin, injected through the `AwsClientFactory` constructor seam every client and `BaseAwsCollector` already accepts, so the hardcoded `*.amazonaws.com` endpoints stay hardcoded. Rewriting before signing is what keeps Floci's credential-scope routing working, and swapping only the origin is what makes one factory serve every service without a path-style or host-prefix special case. The endpoint is the _only_ thing this shim changes — the request shape is production's, which is the point, since a shim that also rewrote the body would stop testing what we send.

Four deliberate constraints. (1) `test/floci/**` is excluded from the root Vitest projects and `test:floci` is **not** in `pnpm run checks`, so the local gate never needs a container. (2) No Docker socket is mounted: every operation used is in-process in Floci, including `CreateDBInstance`, which reaches `available` as metadata with no reachable daemon — a real engine would put a container start on every run to learn nothing extra. (3) EC2 and Lambda are asserted at parse level, not seeded: `RunInstances`/`CreateFunction` need a real container or emulator-wide mock flags whose defaults would then need pinning. (4) Seeds tolerate `EntityAlreadyExists` and friends, so the suite is re-runnable against a long-lived local emulator; without that, a developer's second run fails on every seed. The image is the floating `floci/floci:latest`, so **a red `floci-smoke` run immediately after an upstream Floci release should be re-run once against a pinned tag before it is read as a regression in our parsers**. Out of scope by nature: `ConsoleService`, which calls `signin.aws.amazon.com` through a plain `IHttpClient` rather than the factory seam, and which no emulator serves.

**Assert our parser, not Floci's behaviour.** Every claim in these files is one the production code owes, never one about the emulator, and three early attempts at the opposite were wrong: a chain assertion that `<Account>` reports the role's account (Floci documents routing, not the tag), a Cost Explorer assertion that the period is a bare `YYYY-MM-DD` (AWS _and_ Floci both answer `2026-10-01T00:00:00Z`), and a positive-amount assertion that passed for the wrong reason — Floci reports `0.0000000000` for a bucket with no object in it, so the seed must put real bytes in a real bucket. Where a value is genuinely ours it is asserted exactly: the total is `MoneyUtil.round(sum)` while breakdown amounts stay unrounded, restated rather than imported so a `MoneyUtil` change surfaces as a contract change.

The readiness probe is `sts:GetCallerIdentity` through `StsService` in `global-setup.ts`, **not** a ping. A ping only proves _something_ answers: a stale LocalStack or a leftover process on 4566 answers 200 and then fails every test deep inside a parser, which points at our regexes when the real problem is one process owning a port. It runs once per run rather than per file — Vitest gives each file its own module registry, so a memoized probe would not be shared and a missing emulator would burn the timeout once per file. Its failure text names all three indistinguishable-from-outside cases: nothing listening, something listening that is not an emulator, and **an emulator that answered `2xx` with an unparseable body** — the third is what a query-string Query call looks like, because Floci replies `204` with an empty body and `204` is `response.ok`.

**Never override the CI service container's health check.** The job passes no `options:` to the `floci` service at all, and that is load-bearing. `floci/floci:latest` is the **native** image, built on `registry.access.redhat.com/ubi9-micro`: no shell, no `curl`, no `wget`. Two failed runs cost this, one for `curl` and one for `wget`, and the failure mode is invisible from outside — a `--health-cmd` naming a missing binary makes Docker mark the container unhealthy on the first probe, and GitHub reports only **"Failed to initialize container floci/floci:latest"**, which reads like a broken image rather than a broken health command. Overriding is not just unnecessary but unsafe: Docker runs a `--health-cmd` string through `/bin/sh -c` _inside_ the container, and ubi9-micro ships no `/bin/sh`, so even a correct script path with `|| exit 1` would fail. The image declares its own check in exec form — `HEALTHCHECK CMD ["/usr/local/bin/healthcheck.sh"]`, a bash `/dev/tcp` probe written upstream precisely because the base image has no HTTP client — so omitting `options:` keeps fail-fast _and_ removes our dependence on the image's internals. Anything the container check does not cover is absorbed by the probe above. Two more facts worth not re-deriving: the published tag is the native build even though the repo's `docker/Dockerfile` on `main` is the JVM build (which _does_ install `wget` — reading that file is what produced the wrong `wget` fix), and the shipped `CMD` binds `0.0.0.0` under `-Dfloci.security.allow-unsafe-network-exposure`, which is what makes a published port reachable, so `services:` must not override the command.

**Mock patterns**:

- DAO tests: `createMockDb()` returning `prepare().bind().run/first/all` chain with shared `vi.fn()` refs.
- Services with DAOs: `vi.mock('@aws-access-bridge/backend-data/dao')`.
- Account resolution (migration 0032): a suite that automocks `UserMetadataDAO` must also automock `UserEmailDAO`, or `UserIdentityService` hits a fake `database` with no `prepare`. Automock resolves `undefined`, which the service reads as "no registry row" and falls through to the anchor — the pre-0032 path.
- DAOs that resolve accounts take an injected `UserIdentityService` via a constructor default (`new TokenService(env, identity)`), so a test can pin the account and assert an id-keyed read rather than an address-keyed one.
- AWS clients: `vi.mock('@aws-access-bridge/backend-services/aws/sts')` then `vi.mocked(StsService.prototype.assumeRole)`; same for `CostExplorerService`, `IamService`, `ConsoleService` (partial-mock the module and override only `getSigninToken` to keep URL builders real). Raw parsers tested directly via `provider-clients` `StsClient`/`CostExplorerClient`/`IamClient` with stub signed-fetch.
- Collector registry: `vi.mock('@aws-access-bridge/backend-services/aws/collectors')` with a `CollectorRegistry.getAll` returning hoisted stub collectors (`{ resourceType, collect: vi.fn() }`); `createCollectorRegistry(overrides)` covers service-level override tests; `InjectableCollectorRegistry.withOverrides` covers hermetic tests.
- `TokenService`/`AccessAuthService`: direct lifecycle tests with mocked `UserAccessTokenDAO`; `AccessAuthService.verifyAccessJwt` is pure-static for JWT cases, instance `getAuthenticatedUserEmail` for demo/dev bypass.
- Audit: pass stub `IAuditObserver`s to `AuditService`/`AuditObserverRegistry` to isolate fan-out (`Promise.allSettled` isolation asserted).
- Crypto: `vi.mock('@aws-access-bridge/backend-data/crypto')`.
- Cron tasks in worker tests: `vi.mock('@aws-access-bridge/background/scheduled')` with `tasksForPhase` phase stubs.
- Web services: `vi.stubGlobal('fetch', ...)` with fresh `Response` per call (bodies are single-use).
- Use `vi.hoisted()` for mocks referenced across `vi.mock` factories.
- `beforeEach` + `vi.clearAllMocks()` resets call counts.
- Composition root: `vi.mock('@aws-access-bridge/backend-services/composition')` with `getRequestScope` returning `{ get: () => stub }`; to inject a scope, mock `getRequestScope`, not a deleted `*Factory`.
- **Never re-declare a look-alike of the class under test.** An early `IKeyValueDAO` test defined its own `get`/`put`/`delete` copies, so it asserted the copy's behaviour and a real namespacing bug in `delete` shipped. Extend the real class through a thin subclass that only widens visibility.
- **Assert on the implementation's real contract, not an assumed one.** The SQL allow-list validates the identifier _character set_ (`^[a-z_]\w*$`), not whether a column exists; `EnvParser` coerces a bad value to the default rather than throwing. Both were "fixed" in a test before the implementation was read.
- **Await every async assertion.** A missing `await` on `expect(...).rejects` made the SQL-injection guard assertion a no-op that Vitest warned would fail in the next major.
